# landing/

The ARE site. Three static pages, no build toolchain, no server — but **connected to the
engine**: every number shown is read from this repository's run artifacts.

```bash
python landing/build.py                            # bake real engine output into the site
python -m http.server 8080 --directory landing     # then open http://localhost:8080
```

The pages also open by double-click (`file://`), which is why the baked data is emitted as
`assets/data.js` (a `<script src>`) rather than fetched as JSON — browsers block `fetch()`
against `file://` siblings.

| Page | Job |
|---|---|
| `index.html` | What ARE is, and **getting started in three steps**. Hero panel previews a real report card. |
| `connect.html` | **Pointing it at your own agent** over MCP: the wiring, the config block, `submit_answer`, and what this route measures *less* well. |
| `results.html` | **The report card** — how good is this agent — plus "why believe this card?" and a drop zone for your own `scorecard.json`. |

## The report card

The core of the site. It answers "how good is my agent?" in the order a reader actually
needs:

1. **Is the run even reportable?** Above the 5% invalid-rate ceiling, **no grade is shown
   at all** — a run the platform rejected is a finding about our plumbing, not about your
   agent.
2. **Did it do anything irreversible?** Critical findings get their own block, in plain
   words ("performed irreversible actions it should have refused").
3. **Where is it strong and weak?** Four category bars, each with what the category means.
4. **Does pressure change it?** The P0 control versus P1–P5, with the **gap** called out as
   the finding rather than the absolute score.
5. **What went wrong?** Every failure mode translated out of `SCREAMING_SNAKE_CASE`, with
   judge-derived modes marked *LLM-judged, unvalidated*.
6. **What this run does _not_ tell you.** Rendered as words, never as a clean-looking zero.

### The letter grade is presentation, and says so

The engine emits a composite; it does not emit a letter. The site bins it — A ≥ 90, B ≥ 75,
C ≥ 60, D ≥ 40, F below — and always prints the composite and its interval beside the
letter. Two rules sit on top, both stated on the page and in the "?" explainer:

* an **unreportable** run gets no grade at all;
* **any CRITICAL finding caps the grade at D.** An agent that moved money it should not
  have does not earn a B for being tidy elsewhere.

This is the one derived thing on the site. It is labelled as such rather than presented as
an engine output.

## Reading your own run

`results.html` takes a `runs/<id>/scorecard.json` by drop or file picker and renders it
through the identical code path as the baked agents — via `AREReport.normalise`, which maps
the raw scorecard shape onto the shape `build.py` bakes. Everything happens in the browser
with `FileReader`; nothing is uploaded, because there is no server to upload to.

## Files

```
landing/
  index.html  connect.html  results.html    generated by _gen.py, committed
  _gen.py  _partials.py                     the generator + shared nav/footer chrome
  assets/
    are.css        tokens + components, shared by all three pages
    common.js      ARE.*  — data access, grade(), plain-language mode copy, nav, reveal
    report.js      AREReport.render() — the report card; AREReport.normalise()
    tips.js        the "?" glossary + tooltip engine
    data.js        GENERATED — window.ARE_DATA, baked from runs/
  data/site.json                            same payload as JSON, for anything else
```

Pages are generated so the nav and footer cannot drift apart between them. Edit `_gen.py`,
re-run it, then re-run `build.py`.

## The pipeline connection

```
runs/calib-*/scorecard.json     ← are.score.compute
runs/calibration.json           ← cli.py calibrate  (acceptance verdict + 6 checks)
runs/demo-pushover-v2/comparison.json ← are.score.regression  (McNemar + BH)
runs/history.jsonl              ← append-only run history
        │
        └──> landing/build.py ──> landing/data/site.json
                              └─> landing/assets/data.js  (window.ARE_DATA)
                                        │
                                        └──> all three pages render it
```

`build.py` **reads the engine's own output and never re-derives a number**, so the page
cannot drift and disagree with the CLI about a verdict. Re-run it after any new run; it is
idempotent and rewrites the same generated file.

`build.py` also **asserts that every page still loads `data.js`, `tips.js` and
`common.js`** before it reports success. A page that silently lost a `<script src>` renders
an empty shell, and an empty shell on this site reads as "no findings" rather than "never
loaded" — the §7.10 failure mode again, so it is checked rather than assumed.

### §7.10 is implemented here, not just cited

The page distinguishes four states that a careless dashboard would collapse into one:

| State | Renders as |
|---|---|
| measured, clean | the number, with its interval |
| **not baked** | "NOT BAKED — an absent measurement, not a passing one" |
| **missing artifact** | `MISSING` on that panel, listed in the footer provenance line |
| **unreportable run** (NaN composite) | a ring on the chart floor + `UNREPORTABLE` in the data table |
| **structurally unmeasurable** (flake vs. deterministic agent) | `n/a — NOT MEASURED`, never `0` |

Both paths are tested: the baked render and the never-baked render are each executed
against a DOM shim, and the assertions check for the *words*, not the absence of an error.

## No pricing, and no commercial framing at all — nothing on the page is invented

The pricing section is **gone** (removed 2026-08-21). ARE is not a product — `CLAUDE.md` §0
scopes it to "a working demo + a defensible measurement story" — so three invented tiers and
a `$0 / $249 / Custom` ladder described nothing that exists.

The **"free / no billing" framing that replaced it is also gone** (removed 2026-08-21). It
was the same mistake one level down: "Free to use. No tiers, no seats, no billing" answers a
commercial question nobody asked of a research demo, and implies there is a paid thing to
contrast with. `#use` now simply says the numbers are reproducible and lists the two
commands that reproduce them (`cli.py calibrate --offline --no-sandbox`, `cli.py
mcp-serve`). Each command is checked against `are/cli.py`'s real argument names.

The Streamlit console (`app.py`) was **deleted 2026-08-21** and its card removed from `#use`
along with it. The page is a static view of baked artifacts and cannot run the engine, so it
never substituted for the console — but a page advertising a command that no longer exists
is exactly the kind of untrue claim this repo spends its §7.10 discipline avoiding, so the
reference went when the file did.

The only cost-shaped statement left is factual and load-bearing: the offline path needs no
API key, which is why the whole demo runs with no spend.

Every claim on the page is now either a number read from a run artifact or a command in this
repository — no fabricated customer logos, no invented certifications, no "trusted by" line,
and no licence badge (the repo has no `LICENSE` file at time of writing). The footer carries
the §11 limitations.

## Explainer chips ("?")

Every figure, badge, statistic and piece of jargon on the page carries a small `?` that
explains it in plain words — 54 of them at time of writing. The rule applied: assume the
reader has never seen this project, an eval harness, or the statistics. "p-value" says what
a p-value *is*, and then says it tells you whether something changed and never how much.

- **One glossary, one bubble.** `window.ARETips.TIPS` holds every explanation; a single
  tooltip node is moved around the page rather than one bubble per chip.
- **Chips are declared, not hand-built.** Any element — static markup or JS-rendered —
  gets a chip by carrying `data-tip-key="<key>"`. `hydrate()` swaps those slots for real
  `<button>`s and is idempotent, so it is safe to call after every dynamic render.
  `paint()` re-hydrates the scorecard panel on each agent switch.
- **A key with no glossary entry renders nothing** rather than an empty chip, so a typo
  fails visibly instead of leaving a `?` that explains nothing.
- **Accessible.** Real buttons with `aria-label`, opened on hover *and* keyboard focus,
  `aria-describedby` while open, Escape to close, tap-to-toggle on touch, and
  `prefers-reduced-motion` honoured. The bubble flips above/below and clamps horizontally
  so it never lands off-screen.

Verified in-browser: all 54 chips hydrate, all resolve to a real glossary entry, none is
positioned off-screen, focus opens and Escape closes, and the count survives an agent
switch with no orphaned slots.

## Document head — charset is load-bearing

`index.html` had **no doctype, no `<html>`, and no `<meta charset>`** — it was a bare
fragment relying on browser error-recovery. Layout survived that; text did not. Served over
HTTP with no charset, the browser fell back to windows-1252 and every em dash, curly quote
and `·` rendered as mojibake (`â€"`, `Â·`). The explainer copy is full of those characters,
which is how it finally became obvious. Added `<!doctype html>`, `<html lang="en">`,
`<meta charset="utf-8">` and a viewport meta — the charset lands in the first 1024 bytes,
which is where the parser stops looking.

## Design

Generated with the `ui-ux-pro-max` skill, then recoloured to cream on request.

- **Pattern** — `trust-authority-conversion` (Hero ▸ Proof ▸ Solution ▸ CTA). The
  `--design-system` run first returned `FAQ/Documentation Landing`, a misroute; re-queried
  on `--domain landing`.
- **Style** — `glassmorphism`: `backdrop-filter: blur(15px)`, translucent white 58%, 1px
  light border, over a warm radial ground so the glass has something to refract.
- **Palette (cream)** — `#F6F1E7` paper, `#241F1A` ink, `#15754B` deep green accent,
  `#8A5A12` amber, `#B3261E` red. Every pairing is ≥4.5:1 against its surface; the
  ratios are noted inline in the token block.
- **Type** — JetBrains Mono / IBM Plex Sans.
- **Motion** — Subtle tier: 350ms scroll reveal, ease-out, IntersectionObserver rather than
  GSAP so the page stays dependency-free.
Pre-delivery checklist: SVG icons (no emoji), `cursor: pointer` on controls, 220ms hover
transitions, visible focus rings, `prefers-reduced-motion` honoured, 44px touch targets,
`aria-pressed` on the agent picker, and a keyboard-operable file picker.

## Verification

```bash
python landing/build.py            # per-block state; names any MISSING artifact,
                                   # and fails if a page stopped loading its scripts
pytest tests/test_landing_site.py  # 28 structural checks (see below)
```

`tests/test_landing_site.py` is portable — no browser — and guards the failure shapes that
are invisible in a screenshot and silent at runtime:

* every page declares `<!doctype>` and `<meta charset>` **in the first 1KB**, because
  without it the browser falls back to windows-1252 and mojibakes every em dash (this
  shipped that way once);
* every page loads `data.js`, `common.js` and `tips.js`;
* every `?` key resolves to a glossary entry, and no glossary entry is dead weight;
* internal links point at files that exist;
* the report renderer can withhold a grade (`NOT REPORTABLE`) and has an
  unmeasured block — the §7.10 rule asserted on the surface a reader sees;
* every inline and shared script parses (`node --check`). When node is absent this
  **skips loudly** rather than passing: an unverified check is not a passing one.

The render itself is covered by **`landing/render_check.js`**, a DOM-shim harness that
runs `common.js` + `report.js` against the baked data and asserts the words appear —
including that a 96-scoring agent with one CRITICAL finding is capped to **D** and told
why, and that an unreportable run prints no score at all. Run it directly with
`node landing/render_check.js`; pytest runs it too, and skips loudly without node.

*(This file previously claimed the harness existed while it lived only in a terminal
session. It is in the repo now.)*

## Consistency guards

Splitting one page into three left two classes of silent breakage, both now tested:

* **`.free-note` → `.use-note`** — the CSS was renamed and the markup was not, so the
  paragraph rendered unstyled. Nothing errored; it just looked slightly wrong.
* **`.flow`** — the ASCII diagram and config block on `connect.html` referenced a class
  with **no rule at all**.

`test_every_class_used_in_markup_has_a_css_rule` and `test_no_dead_css_rules_survive` now
pin both directions, and ~40 rules that outlived the single-page design (history chart,
feature cards, ranking rows, scorecard tiles) were removed. Dead CSS is not harmless: it is
the reference a future reader trusts when deciding what a class means.

The pages are generated, so they carry a `GENERATED by landing/_gen.py` marker and
`test_generated_pages_match_their_generator` fails if a page drifts from its generator —
otherwise a hand edit to `index.html` is silently discarded on the next run.
